# lib/font — the Beautiful Boot font, a single source

*[← dev](../../README.md)*

Every program in the repository writes with the same 8x8 font by Michael
Pohoreski (Beautiful Boot, `apple2_hgr_font_tutorial`), completed with the
CP437 symbols. It exists only once, in `bbfont_glyphs.inc`; everything
else is sliced or derived from it automatically.

| File | Role |
|---|---|
| `bbfont_glyphs.inc` | **master**: 256 glyphs, one `bbglyph code, 8 bytes` line each. Bit 0 = leftmost pixel, 8 rows from top to bottom, bit 7 always 0 (7 px wide). It is the only file to edit. |
| `bbfont.inc` | asm: `.include` after choosing `BBFONT_FIRST` / `BBFONT_LAST`; emits the `bbfont` table, `BBFONT_COUNT` and `BBFONT_BYTES_PER_GLYPH` in the current segment. |
| `bbfont_c.inc` | C: the 96 ASCII glyphs `$20-$7F`, generated — this is `hgr_font[]` in `lib/hgrc` (`hgr_font.c`). |
| `../../tools/fonts.py` | Python: `glyph()`, `glyphs()`, `double7()` (x2 HGR), `dhgr_cells()`, `asm_bytes()`, `write_if_changed()`; on the command line, regenerates the derived tables (`--check` in tests). |

## Which font, in which situation

| Situation | Use | Memory cost |
|---|---|---|
| asm, upper-case and digit HUD text (the common case) | `.include "bbfont.inc"` as is: ASCII `$20-$5F`, then `hgr_text8.asm` (`ht_font_lo/hi = bbfont`) or an 8-row STA loop like `chess` | 512 B |
| asm, with lower case | `BBFONT_LAST = $7F` before the include | 768 B |
| asm, any code (LOGO, FONT demo) | `BBFONT_FIRST = $00`, `BBFONT_LAST = $FF` | 2 KB |
| asm, tight resident: only the printed glyphs | a per-game Python generator that picks from `fonts.glyph()` and emits its own indices, like `micro-sokoban/tools/hud_font.py` (45 glyphs, 360 B) | ~8 B/glyph |
| C, HGR | `hgr_puts8` (native 8x8, white) or `hgr_puts` / `hgr_puts_color` (16x16) from [`lib/hgrc`](../hgrc/README.md): `hgr_font[]` comes from `bbfont_c.inc` | 768 B, linked on demand |
| C, DHGR | `dhgr_puts` (same glyphs, white cells) or `dhgr_small` (compact 4x5 font, specific to DHGR, `lib/hgrc/dhgr_small_font.inc`) | 768 B / 1.6 KB |
| DHGR, fine double-width text | planes generated by `chromabreak/tools/generate_fine_font.py` from `fonts.glyph()` | 448 B |
| x2 titles or precomputed digits | `fonts.double7()` (e.g. `arkabreakout/tools/generate_title.py`), `fonts.dhgr_cells()` (`dev/examples/dhgr/src/digits.inc`) | depends on the text |

Interface rule, restated in [`lib/hgr`](../hgr/README.md): normal-size
text stays white; only x2 text may be coloured.

## Changing a glyph

1. Edit the `bbglyph` line in `bbfont_glyphs.inc`.
2. `python3 dev/tools/fonts.py` regenerates `bbfont_c.inc` and `dev/examples/dhgr/src/digits.inc`;
   `make` reruns the games' generators (ARKABREAKOUT title, CHROMABREAK fine
   font, MICRO-SOKOBAN subset) whose Makefiles depend on the
   master.
3. `make test-assets` (in `make test`) fails if a derived table is out of date.

Maze3D keeps its own 8 px font (TMS9918 bit order, `maze3d/src/maze3d.s`,
`font_base`): it is a graphic choice of the game, not a copy of Beautiful Boot.
